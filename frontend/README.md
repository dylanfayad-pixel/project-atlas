# Atlas Terminal

Atlas Terminal is the React and TypeScript frontend
for Project Atlas, a C++20 quantitative research and
historical backtesting project.

## Technology Stack

- React
- TypeScript
- Vite
- Recharts
- Lucide icons
- Vitest
- ESLint

## Current Features

- Interactive market-data visualization.
- Historical BUY, SELL, and HOLD signal display.
- Portfolio performance summary.
- Equity-curve visualization.
- Simulated trade history.
- Runtime portfolio JSON validation.
- Lazy-loaded chart components.

## Local Setup

Requirements: Node.js and npm.

From the repository root:

```bash
cd frontend
npm ci
npm run dev
```

Open the local URL printed by Vite.

## Verification

```bash
npm run test
npm run lint
npm run build
```

## Current Data Sources

The frontend currently reads:

- `public/data/demo_signals.csv`
- `public/data/demo_portfolio.json` (legacy schema v1)
- `public/data/demo_portfolio_v2.json` (legacy cost-aware schema v2)
- `public/data/demo_portfolio_v3.json` (active risk-reporting schema v3)

These are demonstration fixtures.

The portfolio JSON originates from the C++ engine,
but the website does not yet invoke C++ directly.

## Execution Cost Analytics

Schema v2 portfolio results display:

- Total commissions
- Total slippage
- Total recorded execution costs
- Execution costs as a percentage of initial capital
- Per-trade commission and slippage

The frontend validates schemas v1, v2, and v3.

The cost-aware fixture is generated by the C++ engine and
verified against the committed frontend data.

The dashboard does not currently execute C++ backtests
in response to browser requests.

## Important Architecture Boundary

The frontend displays previously generated results.

A backend API for running visitor-selected backtests
has not yet been implemented.

## Limitations

This is an educational research interface.

The demonstration uses synthetic market data and
simplified simulated execution.

No real trades are placed.


## Phase 4 Risk-Control Integration Status

The C++ simulator supports configurable entry
allocation and entry exposure limits.

These controls are not currently selectable
through the React frontend.

The website continues to display static
demonstration portfolio results.

Risk analytics and risk-control configuration
are not yet exposed through the portfolio JSON
v1/v2 frontend contract.

See [risk controls](../docs/phase4-risk-controls.md).

## Phase 4.3 Drawdown Integration Status

The C++ simulator supports a close-observed drawdown
circuit breaker with optional next-bar liquidation.

Atlas Terminal does not currently provide interactive
drawdown configuration or circuit-breaker event history.

The website still reads static demonstration fixtures.

The existing JSON v1/v2 contracts do not expose
drawdown-trigger metadata.

See [drawdown controls](../docs/phase4-drawdown-controls.md).

## Phase 4.4 — Risk Dashboard

Atlas Terminal now supports JSON schema v3.

The Backtests workspace displays:

- Quantitative risk analytics.
- Historical portfolio exposure.
- Maximum observed exposure.
- Configured entry exposure limit.
- Drawdown breach events.
- Successful liquidation events.
- Rejected liquidation events.
- Existing execution-cost reporting.

The active portfolio fixture is generated by
the C++ engine using synthetic data.

Undefined risk statistics display as N/A.

Short synthetic samples can produce unstable
annualized risk statistics.

The dashboard does not execute live trades or
submit backtests to a backend API.

See [Phase 4.4 risk reporting](../docs/phase4-risk-reporting.md).
