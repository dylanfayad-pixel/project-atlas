# 01 — Understanding Project Atlas

## What Is Project Atlas?

Project Atlas is a C++20 quantitative trading research
and backtesting project with a React and TypeScript dashboard.

Its purpose is to evaluate historical trading strategies,
simulate simplified execution, and measure portfolio performance.

## Simple Explanation

Imagine you want to test whether a trading strategy would
have made money using historical prices.

Instead of risking real money, Atlas:

1. Loads historical market data.
2. Checks that the data is valid.
3. Replays the observations chronologically.
4. Asks a strategy whether to BUY, SELL, or HOLD.
5. Simulates eligible orders at the next bar's opening price.
6. Tracks portfolio cash, shares, and equity.
7. Calculates return and maximum drawdown.
8. Exports the results for the dashboard.

## Architecture

```text
Historical OHLCV Data

        v

        v

        |

        |

        |
        v
```

The current dashboard reads a static JSON demonstration
generated by the C++ engine. A live backend API is planned.

## Technologies

### C++20

Used for market-data processing, strategy evaluation,
portfolio simulation, and performance calculations.

### CMake

Configures and builds the C++ application and tests.

### Python

Used for reproducible data generation and integration
verification scripts.

### React

Builds the interactive dashboard components.

### TypeScript

Provides static type checking and validation at the
frontend data boundary.

### GitHub Actions

Automates builds and tests when changes are pushed.

## Current Demonstration

The synthetic SMA crossover example starts with $10,000.

The strategy generates a BUY signal on Day 8 and a SELL
signal on Day 11.

Under next-bar opening-price execution:

- Day 9: Buy 1,000 shares at $10.
- Day 12: Sell 1,000 shares at $4.
- Final equity: $4,000.
- Net profit/loss: -$6,000.
- Total return: -60%.
- Maximum drawdown: 60%.

These are synthetic demonstration results, not live trades.

## Key Concepts to Remember

**Backtesting:** Evaluating a strategy using historical data.

**OHLCV:** Open, High, Low, Close, and Volume.

**Signal:** A strategy's BUY, SELL, or HOLD decision.

**Execution:** The simulated filling of an order.

**Equity:** Cash plus the market value of open positions.

**Drawdown:** A decline from a previous portfolio equity peak.

**Overfitting:** Designing a strategy that works on known
historical data but fails on unseen data.
